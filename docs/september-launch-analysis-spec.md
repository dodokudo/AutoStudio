# 9月ローンチ「セミナー参加者分析」タブ仕様書

- 対象画面: `/launch/[funnelId]` の9月ローンチ
- 作成日: 2026-09-01
- ステータス: ローカル実装済み

## 0. 画面の目的

9/2・9/4・9/5・9/6・9/7の開催日ごとに、参加予定者の人数と属性、実参加・FE購入を確認する。

画面を開いた人が最初に答えられるべき問いは次の2つ。

1. 選択日の参加予定者は何人で、どんな属性の人が多いか
2. 終了後、何人が参加し、何人がFE購入したか

申込日別の集客推移も残すが、セミナー準備の主画面には置かず、下部の補足データへ移す。

## 1. タブ構成

`サマリー | セミナー参加者分析 | 目標・実績入力`

分析データは「分析」を開いたときだけ取得し、サマリーの初期表示を重くしない。

## 2. 画面構成

```text
[9/2] [9/4] [9/5] [9/6] [9/7]  ※日付切り替えのみ

9/2（水）

[参加予定] [実参加] [FE購入] [新規 / 既存]

参加予定者の概要
[参加予定者の要約テキスト]
[年代] [職業] [月商] [流入]

参加予定者の属性
[年代] [職業] [月商] [性別]
[流入媒体・経路]

参加予定者一覧

集客推移（申込日別） ※閉じた補足表示
```

## 3. 開催日の扱い

表示対象は次の5日間。9/3は開催なし。

| 開催日 | 曜日 |
|---|---|
| 2026-09-02 | 水 |
| 2026-09-04 | 金 |
| 2026-09-05 | 土 |
| 2026-09-06 | 日 |
| 2026-09-07 | 月 |

- 初期選択はJSTの今日以降で最も近い開催日
- ローンチ終了後は最終開催日を初期選択
- 開催日を押すと、件数、属性、参加予定者一覧が同時に切り替わる
- 参加予定者は友だち情報 `【2026.9】セミナー申込日` で判定する

## 4. 開催日別の主要指標

| 指標 | 定義 |
|---|---|
| 参加予定 | 選択開催日へ申し込んだユニーク人数 |
| 実参加 | 選択開催日の申込者のうち参加タグがある人数 |
| FE購入 | 選択開催日の申込者のうちFE購入タグがある人数 |
| 新規 / 既存 | 友だち追加日時が8/28 21:00以降なら新規、それ以前なら既存 |

実参加率と申込→FE購入率も同時に表示する。購入ボタンのタップ数は扱わない。

## 5. 参加予定者属性

選択開催日の申込者を母数として表示する。

| 分類 | 値 |
|---|---|
| 年代 | 20代、30代、40代、50代、60代、未回答、複数設定 |
| 性別 | 男性、女性、未回答、複数設定 |
| 職業 | 会社員、フリーランス、経営者、主婦、学生、未回答、複数設定 |
| 月商 | 0円、1〜10万円、10〜50万円、50〜100万円、100〜500万円、500〜1000万円、1000万円以上、未回答、複数設定 |
| 流入 | Threads、Instagram、広告、OG、および取得できる詳細経路 |

- 各カードに人数・構成比・母数を表示する
- 未回答を除外せず、母数に含める
- 同分類のタグが複数ある場合は「複数設定」とし、勝手に1分類へ寄せない
- 最多属性が同数の場合は、1つへ決め打ちせず併記する
- 流入は媒体と詳細経路が重複するため、合計が母数を超える場合がある

## 7. 参加予定者一覧

選択開催日の申込者を次の列で表示する。

- LINE表示名
- 新規 / 既存
- 申込日時
- 年代 / 性別
- 職業
- 月商
- 流入媒体 / 詳細経路
- 申込・参加・FE購入の進捗

20件ずつページングし、表示名・属性で検索できる。個人情報を含むため、既存のAutoStudioログイン内だけで表示する。

## 8. 申込日別データ

8/28〜9/7の申込日別推移は、画面下部の折りたたみ「集客推移（申込日別）」へ置く。

- 当日申込
- 新規 / 既存
- その申込者の実参加 / 参加率
- その申込者のFE購入 / 申込→FE率

開催日別のセミナー準備と混同させないため、初期状態では閉じておく。

## 9. データ定義

- 計測開始: 2026-08-28 21:00 JST
- 計測終了: 2026-09-07 23:59 JST
- ユーザー: `user_core.user_id`
- LINE表示名: `user_core.display_name`
- 申込者: `【2026.9】セミナー申込日` + `セミナー申込計測`
- 参加者: `【2026.8】セミナー参加総数`
- FE購入者: `【2026.9】フロント購入者総数`
- 属性: 年代、性別、職業、売上タグ
- 流入: 流入媒体タグ、流入経路タグ

人数は `user_id` で重複排除する。ブロック済みでも、計測期間中に申込・参加・購入した実績は消さない。
開催日別の参加者数は、参加者タグがあるユーザーの `【2026.9】セミナー申込日` を使って開催日へ帰属する。

## 10. 更新

- APIは `user_core`、`user_tags`、`user_sources`、`user_info` の最新 `snapshot_date` を読む
- 1日1回のLステップCSV取込後、次に画面を開くと最新値へ切り替わる
- ブラウザHTTPキャッシュは使わず、画面内では5分間の重複取得だけ抑える
- 手動更新ボタンは置かない
- 画面に `データ基準 YYYY/M/D CSV` を表示する

## 11. 非対象

- LINE配信内容、開封率、クリック率
- 来訪者数
- 購入ボタンのタップ数
- 分析画面からのタグ編集
- リアルタイム連携
- BE購入者の主画面化（今回はFE売上が主目的）
